# Steps for Rerunning Steps of Our Pipeline

## System Requirements
1. GPU: RTX-capable NVIDIA GPU with sufficient VRAM
2. System RAM: At least 32GB RAM recommended, 16GB VRAM
3. Nvidia Drivers installed
4. Python Version:
  Isaac Sim 4.X: Python 3.10
  Isaac Sim 5.X: Python 3.11

Isaaclab setup guide: https://isaac-sim.github.io/IsaacLab/main/source/setup/installation/index.html
Install libraries in requirements.txt

## Running RL Training
RL Training can be run by first downloading the motion files from the lafan1 dataset using at the following link:
https://github.com/ubisoft/ubisoft-laforge-animation-dataset

Then, utilize the csv_to_npz.py converter for each file that you'd like to include in your motion with 
```
python csv_to_npz.py --input_file LAFAN_Folder/motion_name.csv --input_fps 30 --output_name motion_name --output_fps 50
```

Once the motion artifacts have been saved to wandb, you may run them using the following command in scripts/rsl_rl/
```
python train.py \
    --task Isaac-Velocity-Flat-G1-v0 \
    --registry_name wanddb_username/model-registry/motion_artifact:latest \
    --num_envs 4096 \
    --max_iterations 1000 \
    --seed 42 \
    --headless
```

The training loops take a long time to run given isaacsim constraints.
For user convenience, we have included 10 policies and motion files that we trained them from under vae/policies

## Running VAE Training
To run VAE training, we have written a script to conduct iterative DAGGER training. The user just needs to run

```
./dagger_training.sh
```

Note that the user can choose which motion files to use when running their VAE training script.
Make sure that policy and motion file names match the motion names as shown below:

```
MOTIONS=(
    "dance1_subject2"
    "dance2_subject3"
    "walk1_subject2"
    "walk1_subject5"
    "walk2_subject3"
    "run1_subject2"
    "run2_subject1"
    "run2_subject4"
    "jumps1_subject1"
    "jumps1_subject2"
)
```

The user can control the data collection and training parameters in this code:

```
# Training parameters
NUM_DAGGER_ITERATIONS=5
VAE_EPOCHS=100
BATCH_SIZE=2048
LEARNING_RATE=5e-4
BETA=0.01

# Trajectory collection parameters
NUM_ENVS=300
NUM_ROLLOUTS=150
ROLLOUT_LENGTH=500
MIN_TRAJ_LENGTH=150
```

## Training the Diffusion Model
Once the VAE model has been trained, we use it to generate future trajectories.
Navigate to the test_diffusion folder and run ./acquire_data.sh

the acquire_data.sh file contains the following lines that may be modified based on the user's dataset.
Ensure again that the motions used matches the name of the motion file saved runs on wandb.
```
VAE_MODEL_PATH="../vae/models/iter4/vae_model_100_iter4.pth"
OUTPUT_DIR="./data"
NUM_ENVS=5000
NUM_ROLLOUTS=100
ROLLOUT_LENGTH=150
OU_SIGMA=0.1

mkdir -p $OUTPUT_DIR

MOTIONS=(
    "walk1_subject2"
    "walk1_subject5"
    "walk2_subject3"
    "run1_subject2"
    "run2_subject1"
    "run2_subject4"
)
```

After the data has been generated, they will have been saved to /data

The user can then run train_diffusion.py using python train_diffusion.py with no extra arguments.

Note that the trajectory file locations currently point to the data that has already been saved.
The user should modify the names of the saved trajectories in the case that their own data is generated.

```
  model = DiffusionTransformer()
  scheduler = Diffusion_Scheduler(beta_begin=1e-4, beta_end = 0.02, steps = 200, cosine = False)

      "data/iter4_walk1_subject2_fixed.pt",

      "data/iter4_run2_subject4_fixed.pt"
  ]
  model = diffusion_training(model, scheduler, filepaths = trajectory_files)
```

## Generating Outputs with the Diffusion Model

Unfortunately, we could not include the diffusion_checkpoint_1000.pt on the github because of file size constraints. We've attached
a separate link for it here: https://drive.google.com/drive/folders/1cY18e5APXTEBCkw80RaKS9QzV4bkMqI-?usp=sharing
It should be inserted into tested_diffusion/models

Finally, we did not implement the gradient-based trajectory generative motions specified in the beyondmimic paper.
However, we did perform trajectory generation using the diffusion starting from a motion file state (with history generated by a VAE).

To generate trajectories, use the following command.
```
python test_diffusion.py \
    --task Tracking-Flat-G1-v0 \
    --vae_path ../vae/models/iter4/vae_model_100_iter4.pth \
    --diffusion_path ./models/diffusion_checkpoint_1000.pt \
    --motion_name walk1_subject2 \
    --num_episodes 10 \
    --episode_length 500 \
    --denoising_steps 20 \
    --history_length 4 \
    --prediction_horizon 8 \
    --video_dir ./videos \
    --headless \
    --enable_cameras
  ```

  If the length of the trajectory generated exceeds 100 timesteps, then it is saved to ./videos. Note that the model is not very robust when running so increasing num_episodes will increase the likelihood of a successfully generated video output.
